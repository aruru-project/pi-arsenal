# 游戏 UI/UX

## 设计方法

1. **确定当前玩家任务。** 从需求中提取玩家要达成的目标、已有信息、可选行动和结果。已有玩法、流程与视觉基准作为设计起点。
2. **组织画面。** 突出当前最重要的信息和操作；把关联的名称、数值、说明与按钮放在一起。复杂内容按用途分组或逐步展示，而非按固定数量拆分。
3. **连接流程。** 明确入口、下一步、返回以及选择何时生效。保留必要的条件分支；返回修改时，让玩家知道已有输入与进度是否保留。
4. **表现状态。** 区分焦点、选中、可用和禁用。操作后及时更新关联数据；等待、完成和失败有可理解的反馈，不可选项能解释原因。
5. **控制操作成本。** 去掉重复输入和多余确认；高代价误操作提供恰当保护。鼠标目标容易命中，键盘焦点清晰可见，按目标设备检查文字大小与对比度。
6. **保留游戏体验。** 让场景、字体、声音和动效服务游戏氛围，同时保证关键内容可读。区分无意义的操作障碍与有价值的决策、探索和叙事节奏。

## 按任务产出

- **概念与示意图：** 表现布局、关键状态及页面衔接；未知内容明确使用占位，不把自拟数据当作游戏规则。
- **实现与交互检查：** 沿实际玩家路径检查操作、反馈、返回和数据保留。静态图只用于判断视觉，行为结论来自真实交互。
- **评审建议：** 说明玩家在哪里受阻、造成什么影响，再给最小调整；将可用性问题与审美偏好分开。没有具体影响的法则偏离，不单独列为缺陷。
